soloFactory × Claude Code: environment audit

What a Claude worker actually loads when soloFactory runs in this repo, where that context overlaps, conflicts or goes missing, and what the only Claude-provider run on this machine measured. Written 2026-11-05 against soloFactory 0.10.3 and Claude Code 2.1.296.

Bottom line. The launch flags do their job: user plugins, hooks, MCP servers and output style are excluded from workers (verified in a real worker's init record). What still reaches every worker is a chain of instruction files that each tell it to go read more files under ~/.aai, several of which it is not allowed to read in headless mode, plus a shell rule and an allowlist that the workers kept bumping into. None of that is the dominant cost. The dominant cost is turn count: the one Claude run with logs here spent 2,729 turns across 71 workers at roughly 70K tokens of context per turn, with 3 to 4 MB recovery-request files sitting in .factory/ for workers to read. Antigravity sees none of the ambient chain and none of the factory's repair/recovery loop.

Caveat. The run Lou described (the PRD that exhausted the weekly limit without producing an app) was not found on this machine. The numbers below come from the medialibrary run under ~/Documents/photo-library-prototype, which did reach "live and verified" on 2026-10-16 after nine days. It is the closest evidence available, not the failing run itself.

1. The launch contract

Every stage spawns one claude -p process with the project folder as cwd (src/providers.mjs, claudeRun):

claude -p --output-format stream-json --verbose
       --model opus --effort medium           # reasoning stages: opus, effort low
       --setting-sources project,local --strict-mcp-config
       --permission-mode acceptEdits          # read stages: plan
       --disallowedTools Agent
       --allowedTools "Bash(npm install:*)" "Bash(npm test:*)" "Bash(npm run build:*)"
                      "Bash(node .factory/check-plan.mjs:*)" "Bash(node --test:*)"
                      "Bash(ls:*)" "Bash(git ls-files:*)" "Bash(git status:*)"
                      "Bash(git diff:*)" "Bash(git log:*)" + proof commands
stdin: <stage prompt> + "Shell: ... Only plain single commands are approved ...
        a command with cd, &&, ;, |, a loop, a heredoc or a redirect is denied"

Hard timeout 45 minutes per worker, no idle timeout, API-key environment stripped so the subscription is billed.

3. Findings, ranked

High · 1. Instruction chain points workers at files they cannot read

What The project anchor says read .aai/instructions.md; that file says load the parent folder's instructions first; the parent says load ~/.aai/identity.md, purpose.md, context.md, memory.md and ~/.aai/rules/core.md, then ~/.aai/rules/coding.md. In this repo the ancestor .claude/CLAUDE.md repeats the same demand and adds ~/.aai/rules/operational.md and the identity modules.

Evidence Workers obeyed. Three medialibrary workers called Read on ~/.aai/rules/coding.md; all three were denied (permission_denied, "needs approval") because headless mode confines Read to the project tree. One more tried the vendored copy under the parent's .ailib/, also denied. verified

Why it hurts Each attempt is a wasted turn, and the worker then proceeds without the rules it was told are mandatory, having been primed that it is working out of compliance. The instruction can never be satisfied from inside a project folder.

Fix Remove every "read ~/.aai/..." instruction from the build-side chain (project anchor, project instructions.md, parent instructions.md template, ancestor .claude/CLAUDE.md when the project lives under it). What a worker must obey belongs in the stage prompt the factory already builds, which is the one channel the factory controls.

High · 2. Parent-folder instructions written for a human-driven session, read by the build worker

What The medialibrary parent .aai/instructions.md says: run make to see the pipeline, read HANDOFF.md and checkpoint.md "at session start", change spec/ by decision, "make release owns VERSION", rewrite HANDOFF before ending. In this repo the equivalent my-folder instructions say "do not drive the interview", "never start a real build", and describe a projects/<id>/app/ layout that no longer exists.

Evidence Parent HANDOFF.md is 70K chars and checkpoint.md is 101K chars. make is not in the allowlist. The factory's contract is .factory/{PRD,PLAN,ACCEPTANCE}.md, which the project instructions name one paragraph later. verified

Why it hurts Two governing documents, two different process models, loaded in the same turn. The worker either burns context reading 170K chars of handoff it cannot act on, or ignores a file it was told governs "the factory as a whole".

Fix The project instructions.md template should stop chaining to the parent. The parent folder governs the operator's session with the factory, not the worker's build.

High · 3. Live-app section tells the agent in the project folder to refuse the work

What live-app.md is appended to every project's .aai/instructions.md: "If the owner opened you here directly and asks to change the app, recommend the factory instead… make the smallest edit and tell them the factory doesn't know about it." The factory's own worker runs in exactly that folder with exactly that file loaded.

Evidence Present in templates/project/live-app.md and in the medialibrary project. verified Whether a worker ever acted on it is not measurable from the logs. unknown

Fix Gate it: "If no .factory/ run is in progress…" or move the owner-facing advice to a README the worker is not told to obey.

Medium · 4. Shell rule and allowlist fight the model's habits

What The stdin rule forbids cd, &&, pipes and redirects and says to search with Grep. The allowlist covers nine command shapes. Opus reaches for grep -n, git grep, node -e, git stash, git worktree add and node tools/build.mjs anyway.

Evidence 287 permission denials across the run, about 10% of all 2,729 turns. Joined to their commands: Bash grep/git grep variants dominate, then node -e one-liners, then git stash/restore/worktree, then reads of files in /var/folders and the scratchpad that the worker itself had written. verified

Why it hurts Every denial is a full round trip at ~70K tokens of context, and the retry is usually a longer command.

Fix Allow Bash(grep:*), Bash(git grep:*), Bash(node -e:*) and Bash(node tools/*:*), or state in the shell rule that Grep is the only search path and node -e is denied, so the model stops guessing. Add --add-dir for the scratchpad if workers are expected to read their own task output.

Medium · 5. Recovery artifacts in .factory/ are megabytes, and workers read them

What recovery-request-*.json files are 2.4 to 3.9 MB; recovery-plan-*.json 2.4 to 3.1 MB. Workers read .factory/ 185 times for 13.6 MB total, and shelled node -e "require('./.factory/recovery-request-…json')" to dig into them (denied, see finding 4).

Evidence File sizes from ls -S .factory; read census from tool_use records. verified Lou's standing rule is no agent prompt over 200K chars.

Fix Upstream: the factory should write the worker a slice-sized request file and keep the full ledger elsewhere. This is factory code, not environment, but it is the single largest measurable input cost.

Medium · 6. Irrelevant project memory in this repo's ancestor

What When the default project under .solofactory/projects/default is used, every worker turn carries /Volumes/Extreme Pro/users/loudalo/.claude/CLAUDE.md plus three rule files: writing/voice rules, skill-authoring rules, a Notion MCP workaround, an SVG-to-Notion workflow, and a pointer to the coding rules it cannot read (finding 1). 18.5K chars, roughly 5K tokens, on every call. inferred from the documented memory walk; the medialibrary run was not under this ancestor.

Fix Either run builds under a folder with no .claude/CLAUDE.md ancestor (as the medialibrary install did), or add a CLAUDE.md at the project root that says nothing beyond the factory anchor and rely on SOLOFACTORY_ROOT pointing outside the ancestor chain. Cheapest check: run one worker with --debug and inspect which memory files it lists.

Low · 7. Duplicate anchor via AGENTS.md

Project AGENTS.md and CLAUDE.md are identical. The builtin agents-md plugin is active in workers, so the anchor is probably loaded twice. Small cost, easy delete: keep AGENTS.md for Codex and let CLAUDE.md hold only what differs. inferred

Low · 8. Effort and model choices

Reasoning stages (specification, plan, review, recovery-plan) run Opus at effort low; build stages at medium. All 60 worker inits in the medialibrary run were claude-opus-5-5. Low effort on the plan and review stages is a plausible contributor to the repair loop (15 repair workers, 53 recovery slices) that then costs far more than a higher-effort plan would have. inferred

Low · 9. Omissions

  • No CLAUDE.md or AGENTS.md at the soloFactory repo root, so nothing shields the default project from the ancestor files.
  • No project-level .claude/settings.json in the generated project, so no deny rules protect data/ or .env in headless mode; the user-level deny list is excluded by design.
  • Stale launch.json entries in this repo point at old scratchpad paths. Harmless to workers, confusing to the operator.
  • User env inheritance (compaction thresholds) is undocumented under --setting-sources; the 176K-token single call suggests the 75% / 250K settings may be reaching workers. Worth one --debug run.

5. What Antigravity does not see

  • No ancestor memory walk, so none of the .claude/CLAUDE.md or rules files.
  • No .aai/ chain unless the agent is told to read it; it is not.
  • No 58 builtin skill descriptions in every call.
  • No per-command allowlist denials; the agent runs the shell it wants.
  • No factory repair/recovery loop. One agent, one conversation, one PRD, the operator watching. The comparison is therefore between a single long session and 71 cold-started workers that each re-read the project.

6. What to do first

  1. Strip every "read ~/.aai/…" from the build chain and cut the parent-folder chaining in templates/project/instructions.md. One edit, removes findings 1 to 3.
  2. Widen the allowlist to the commands workers actually asked for, or make the shell rule name the denied shapes explicitly. Removes most of the 10% denial tax.
  3. Cap the request file a worker is pointed at (slice-sized, under 200K chars). Largest measurable input saving.
  4. Raise reasoning-stage effort from low to medium or high and measure repair count on the next run.
  5. Run one worker with --debug to settle the two unknowns: which memory files load in this repo, and whether user env reaches the worker.
