Anatomy of SoloFactory

A local-first software factory for one developer. It interviews you, freezes a PRD/plan/acceptance contract, drives your existing Codex or Claude Code subscription session to build the app, runs deterministic gates it owns itself, repairs bounded failures, and deploys the result on a loopback port. No API key is ever requested or stored. These five drawings are the machine behind that sentence.

01Architecture

Two things are worth drawing. First, what actually runs: one Node process on loopback, two front ends onto it, and a language model that lives outside it. Second — the real design decision — the line between what the model is allowed to do and what only local code may do.

local controller code — owns state and gates semantic worker — the subscription CLI a gate or a failure path

02Functional flow

A run is one release of one project. Every new run plans before it builds, and an independent reviewer has to approve that plan — bound to its digest, the frozen contract and a token — before a line of application code is written.

03When a gate fails

Repair is where an autonomous builder normally burns a subscription down. SoloFactory's answer is a small budget and three independent reasons to stop.

04Top-level state machine

Twelve canonical states. Seven are active, four are parked, one is terminal success. Every edge out of the parked band is an owner action — the controller never resumes, retries or starts over on its own.

05What the drawings leave out

  • The Factory Guide interview has its own contract: every reply must satisfy a strict JSON schema, and every check in the compiled brief must be provable offline on this machine. Checks that need a live account, a clock or a fixed path are rewritten and moved to a "checked by hand after install" list that no build or review chases.
  • The watchdog is an observer, not a state. It labels the active run Working, Waiting for command, Progress unknown, Progress needs checking, Recovering or Action needed. It never stops a worker — the idle and hard caps remain the deadlines.
  • There is a legacy path: the older single-pass and slice strategies. New runs are all planned-feature runs (planVersion: 2); older runs still resume on their own path.
  • The repository ships two products from one tree: the Node app under src/ and public/, and an installable agent skill under distro/ that sets a folder up as a factory and drives it from chat.
