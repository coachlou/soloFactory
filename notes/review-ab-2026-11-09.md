# Review A/B: SOLOFACTORY_FEATURE_REVIEW=risky vs all, household-inventory (2026-11-09)

Commit under test 395284c. Four paid runs, alternating A (all) and B (risky), Opus low, one brief. n=2 per arm.

## Bottom line

**Not enough to make `risky` the default. Keep it off; the cost saving is about 3%, far under the 15% bar, and the catch rate is unmeasured.**
Outcomes were identical (4 of 4 passed, no parks, no recovery). Median cost per feature fell from $0.815 to $0.79 (-3%), a difference inside run-to-run noise (arm A alone ranged $0.75 to $0.88). One finding landed on a skipped feature (PERSIST in run 2), so the skipped reviews are not free of defects, but it was caught by the final review and fixed with one repair.

- Run 1 (all): scoped review of MOVE hit two "review evidence cannot escape the project" gate failures (malformed review, not a content block). - Run 2 (risky): FOUNDATION and PERSIST skipped. Final review blocked MH-15 with BUG-1 on PERSIST: data dir created only on first save, not at startup. Fixed in 1 repair. This is the one skipped-feature finding.
- Run 3 (all): zero review blocks. Two gate failures were ordinary test/proof failures (FOUNDATION test; ITEM-VALIDATE proof).
- Run 4 (risky): FOUNDATION and PERSISTENCE skipped, no findings on either. LOCATIONS and ITEMS (risky, so reviewed) each had 2 scoped reviews with blocks (LOC-CRUD, MH-1; three under-asserting tests in test/items.test.js), repaired. So risky does still review where the gate says risky, and those reviews did block.

## Criteria

1. **Savings (median costPerFeature down at least 15%, wall time not up): NOT MET.** -3% cost per feature ($0.815 to $0.79; with n=2 the median is the mean). Total cost per run -6.6% but features per run vary. Wall time did not rise (27 to 25.5 min mean). Reviews skipped were only 2 of 11-12 features, the gate marks most of this brief as risky, so the ceiling on savings here is small.
2. **Same outcome, no new parks: MET.** 4 of 4 passed, 0 parks. Final review continuation count was not extracted, so "no more than one continuation" is not verified, but nothing parked.
3. **Catch rate holds: NOT MEASURABLE with this data.** Arm A had 3 final-review defects in one run and zero scoped-review content blocks that the risky arm would have skipped, so the OFF arm did not show the required 2 scoped blocks for a valid comparison. Arm B had one defect on a skipped feature (PERSIST data-dir-at-startup, a class-1/3 style gap: a requirement checked in the final review rather than at feature time) that the final review did catch, which is mild evidence the final review catches what skipping misses. No post-hoc audit (b) or manual check (c) was done.
4. **No new recovery entries: MET.** recoveryPhase null in all four runs, no feature-recovery.

## Recommendation

Do not make `risky` default on this evidence. The gate classifies most household-inventory features as risky, so the saving is small (about 3%, plus any final-review-time cost, not separated here), and the catch-rate criterion needs a brief that reliably trips scoped reviews (option 3a) or a post-hoc audit (3b). If anything, run `risky` on a bigger or messier brief. n=2 per arm, one brief, and cost noise within arm A (up to 17%) exceeds the effect; treat these as a tripwire, not a measurement.
